apaf.runtime.properties — Runtime Properties Plugin

Overview

The apaf.runtime.properties plugin exposes the NPA runtime property system as a REST API and provides a UI for administrators to view and edit runtime configuration values without restarting the server. Properties are declared by plugins via the npa.runtime.property.provider extension point and stored in memory. The service is accessible as:
let properties = plugin.getService('properties');

Service Name

'properties'

Property Types

TypeDescription
stringFree-form text value
intInteger numeric value
booleanBoolean (true / false)
percentageInteger value constrained to 0–100
momentDate/time value (moment.js compatible)

REST API

MethodPathRoleDescription
GET/runtime-properties/administratorGet all runtime properties
GET/runtime-properties/:nameoperatorGet the value of a named property
PUT/runtime-properties/operatorSet or update a runtime property value

Declaring a Property

Any plugin can declare a runtime property via the npa.runtime.property.provider extension point in its manifest.json:
{
  "point": "npa.runtime.property.provider",
  "id": "my.plugin.timeout.property",
  "name": "my.plugin.timeout",
  "type": "int",
  "value": 30000,
  "description": "Timeout in ms for my plugin operations"
}

Workflow Nodes

apaf.runtime.properties contributes two workflow nodes:
  • "Get Runtime Property Value" — reads the value of a named property into the context
  • "Set Runtime Property" — writes a value to a named property at runtime

Notes

  • Property values are in-memory — a server restart resets them to their declared defaults.
  • Locked properties cannot be edited via the UI (they are read-only in the admin page).
  • Well-known properties: scheduler.tick.timeout (apaf.scheduler), workflow.global.timeout (apaf.workflow).
