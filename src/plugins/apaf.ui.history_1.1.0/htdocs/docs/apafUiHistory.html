apaf.ui.history — User Interaction History Plugin

Overview

The apaf.ui.history plugin provides a generic, per-user, per-context interaction history service for APAF applications. It is conceptually similar to the browser's address-bar autocomplete: each named context maintains a ordered list of the last N entries submitted by the authenticated user.

Key design decisions:

  • Dedicated database — history is stored in its own CouchDB database (apaf_history), completely separate from the apaf_users and application-data databases. Since version 1.1.0, the database is managed through the built-in history datatype registered with apaf.datatype: the CouchDB connection settings (APAF_COUCH_DB_* environment variables) are those of apaf.datatype, and the database is created automatically if missing.
  • Sensitive-field exclusion — fields marked "sensitive": true in the component configuration are never sent to the server and therefore never stored. Passwords, API keys and similar secrets remain local to the browser session only.
  • Automatic de-duplication — when the same entry is submitted twice, the existing copy is removed and the entry is prepended, so it always appears at the top of the history list.
  • Configurable size — the maximum number of retained entries is controlled per-context via the maxSize configuration property (default 10).

The plugin ships a client-side UI component (apafHistory.HistoryInput) that wraps a set of input fields into a form with dropdown recall buttons. Any consuming APAF application or snippet can drop this component into its layout to immediately gain history recall without any additional server-side code.

REST API

All handlers are mounted on the router path /apaf-history and require the user to be authenticated (no specific role is needed by default).

GET /apaf-history/:context

Returns the list of stored history entries for the authenticated user and the given named context.

ParameterWhereDescription
contextpathNamed history context, e.g. ssh.terminal

Response:

{ "status": 200, "message": "ok", "data": [ { ... }, ... ] }

An empty array is returned when no history exists yet for this user × context pair. Entries are ordered most-recent first.

POST /apaf-history/:context

Pushes a new entry into the history for the authenticated user and the given named context. The entry is prepended (most-recent first). Identical entries are de-duplicated. Entries beyond maxSize are silently evicted.

FieldTypeDescription
entryobjectRequired. Key/value map of the values to store. Sensitive fields must have been stripped by the caller before this call.
maxSizenumberOptional. Maximum entries to keep for this context (default 10).

Response:

{ "status": 200, "message": "created|updated", "data": { /* updated CouchDB document */ } }

CouchDB Document Structure

One CouchDB document per user × context pair is stored in apaf_history (datatype history, fields userId, context, maxSize and entries of type json). The document id is deterministic and supplied by the plugin:

{
  "id":      "<userId>.<context>",   // deterministic key
  "userId":  "alice",
  "context": "ssh.terminal",
  "entries": [
    { "host": "192.168.1.10", "port": 22, "username": "admin" },
    { "host": "10.0.0.5",     "port": 22, "username": "root"  }
  ],
  "maxSize": 10
}

UI Component: apafHistory.HistoryInput

The HistoryInput component is registered in the apafHistory namespace (type string: "apafHistory.HistoryInput"). It renders a set of labelled input fields, each equipped with a dropdown recall button (except sensitive fields). A configurable submit button collects all field values and invokes a callback.

Configuration Properties

Field Descriptor Properties

PropertyTypeDefaultDescription
namestring—Required. Logical field name; used as the property key in the values object and in stored history entries.

typestring"text"HTML input type: text, password, number.

Public JavaScript API

Once rendered, a HistoryInput instance is accessible via npaUi.getComponent('<id>') and exposes the following methods:

MethodReturnsDescription
getValues()objectReturns the current field values as a plain object: { fieldName: value, ... }.
setValues(obj)voidFills the form fields from the given object. Fields absent from obj are left unchanged.
loadHistory()voidRe-fetches history entries from the server and refreshes the dropdowns. Called automatically on first render.
saveHistory(values)voidStrips sensitive fields from values and posts the entry to the server. Call this after a successful operation to persist the entry.

DOM Event

In addition to the onSubmit global callback, the component dispatches a custom DOM event apafHistory:submit that bubbles up from the component's root element. The event.detail object contains:

PropertyDescription
componentThe HistoryInput component instance
valuesCurrent field values (including sensitive fields)
contextThe configured context name

Minimal Usage Example (JSON configuration)

{
  "id": "mySshForm",
  "type": "apafHistory.HistoryInput",
  "version": "1.0.0",
  "configuration": {
    "context": "ssh.terminal",
    "maxSize": 10,
    "submitLabel": "Connect",
    "submitIcon": "/uiTools/img/silk/connect.png",
    "onSubmit": "onConnectClicked",
    "fields": [
      { "name": "host",     "label": "Host",     "type": "text",     "sensitive": false },
      { "name": "port",     "label": "Port",     "type": "number",   "sensitive": false },
      { "name": "username", "label": "Username", "type": "text",     "sensitive": false },
      { "name": "password", "label": "Password", "type": "password", "sensitive": true  }
    ]
  }
}

Minimal Usage Example (JavaScript onSubmit handler)

function onConnectClicked(values){
  // values.host, values.port, values.username are available
  // values.password is available in memory but was NOT stored
  myApi.connect(values, function(err){
    if(!err){
      // Only persist the entry on success
      let comp = npaUi.getComponent('mySshForm');
      comp.saveHistory(values);  // password is stripped automatically
    }
  });
}

Integration with Existing Plugins

To add history recall to an existing APAF view (e.g. the SSH terminal from apaf.ext.ssh), replace the plain input elements with a HistoryInput component host <div>, register the component configuration, call npaUi.render('user-app'), and update the submit handler to call saveHistory(values) on success.

No server-side changes are needed in the consuming plugin. The only dependency to add in its manifest.json is:

{ "type": "plugin", "id": "apaf.ui.history", "version": "1.0.0" }
