apaf.micro.services — APL Micro-Services Plugin

Overview

The apaf.micro.services plugin lets developers create, manage and invoke server-side micro-services written in APL (APAF Programming Language). Each micro-service is a named, versioned record stored in CouchDB. It carries an APL script that is compiled and executed on demand for each matching incoming HTTP request.

The plugin exposes:
  • A management UI accessible from the Development menu (role: developer)
  • A management REST API for CRUD operations on micro-service records (role: developer)
  • A public invocation API that routes live HTTP calls to the matching script (no role restriction by default)

Micro-service record structure

Each micro-service record is stored in the apaf_micro_services CouchDB database with the following fields:
FieldTypeRequiredDescription
namestringyesUnique name of the micro-service (used in the invocation URL).
versionstringyesVersion string (used in the invocation URL).
methodstringyesExpected HTTP method: GET, POST, PUT or DELETE.
descriptionstringnoHuman-readable description.
enabledbooleannoWhen false, invocation returns HTTP 503. Defaults to false.
restrictedToRolestringnoWhen set, only authenticated users holding this APAF role can invoke the micro-service. Empty string means no restriction.
sourcestringyesAPL source code. Must define a function process(request, response).
apiDocobjectnoOptional OpenAPI descriptor object documenting the micro-service interface.

Invocation API

All four HTTP methods are routed through the same URL pattern. The micro-service is looked up by name and version and its stored method field must match the incoming HTTP method.
MethodURLSecurity role
GET/apaf-micro-services-api/api/:name/:versionnone (or restrictedToRole)
POST/apaf-micro-services-api/api/:name/:versionnone (or restrictedToRole)
PUT/apaf-micro-services-api/api/:name/:versionnone (or restrictedToRole)
DELETE/apaf-micro-services-api/api/:name/:versionnone (or restrictedToRole)
The plugin builds a request context object from the incoming HTTP request and executes the APL script with it. The response object populated by the script is returned as the data field of the JSON response. Response format:
{ "status": 200, "message": "ok", "data": <response object populated by the APL script> }
Error responses:
HTTP statusCondition
404No micro-service found with the given name and version.
400HTTP method does not match the micro-service's declared method.
403Caller does not hold the required restrictedToRole.
503Micro-service exists but is disabled (enabled: false).
500APL compilation or execution error.

Request context passed to the APL script

The script receives a request object built from the incoming HTTP request and an empty response object. Both are pre-loaded into the APL execution context as global variables.
VariableFieldDescription
requestrequest.methodHTTP method string: "GET", "POST", etc.
request.paramsURL path parameters object (e.g. request.params.id)
request.queryURL query-string parameters object
request.bodyParsed JSON request body (for POST / PUT; empty object for GET / DELETE)
request.headersHTTP request headers object
response(initially empty)Object populated by the script; its value is returned as data in the HTTP response.
The caller appends process(request, response); to the stored script source before execution, so every micro-service script must define a function with that exact signature. Built-in function available during execution:
FunctionDescription
print(msg)Writes a message to the APAF server log at info level, prefixed with the micro-service name and version.

Management REST API

All management endpoints are mounted under /apaf-micro-services-api and require the developer security role.
MethodURLDescription
POST/queryQuery micro-service records using a CouchDB Mango selector. Body: { "selector": { ... } }.
GET/:idRetrieve a single micro-service record by its UUID.
POST/Create a new micro-service record. Body: full record object.
PUT/Update an existing record. Body must include id and _rev fields.
DELETE/:idDelete a micro-service record by its UUID.
POST/checkSyntax-check an APL source string without saving it. Body: { "source": "..." }. Returns { "success": true|false, "error": "..." }.

Management UI

The micro-service management console is accessible from the Development menu (requires the developer role). It provides a form-based editor for creating and editing micro-service records, with an integrated APL syntax checker powered by the /check endpoint.

Database

Micro-service records are persisted in the apaf_micro_services CouchDB database, which is created automatically by APAF on first startup.
