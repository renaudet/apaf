apaf.registry.client — Registry Client Plugin

Overview

The apaf.registry.client plugin lets an APAF instance exchange features with a remote APAF Registry (an APAF instance started with --application registry, see the apaf.registry plugin). A feature is a set of roles, datatypes, workflows, code fragments, applications and rule-data tables packaged under a name and a version.

Manage Features page

The plugin adds a Manage APAF Features entry to the Administration menu (administrator role). The page offers two functions:
  • Export Feature — select the resources of this instance, describe the feature and publish it to the Registry
  • Import Feature — search the Registry catalog by name and/or category and install a feature on this instance
Installation is idempotent: resources that are already defined (same name, and same version when applicable) are left untouched.

Configuration

The Registry location is read from the plugin manifest, and can be overridden with environment variables:
Environment variableDefaultDescription
REGISTRY_HOSTtwinxeon.onlineRegistry host name
REGISTRY_PORT5008Registry TCP port
REGISTRY_SSL_ENABLEDtrueUse HTTPS to reach the Registry

REST API

MethodPathRoleDescription
POST/apaf-registry/publishadministratorPublish a feature to the Registry
GET/apaf-registry/catalog(authenticated)Search the Registry catalog (category, name, summary query parameters)
GET/apaf-registry/feature/:id(authenticated)Get a full feature definition from the Registry
PUT/apaf-registry/installadministratorInstall a feature on this instance

Relationship with other plugins

This plugin is a standalone replacement for the client side of apaf.registry 1.0.0 and for the manageFeatures page formerly served by apaf.statics. It serves its own static resources under /apaf-registry-client-ui. It must not be deployed together with apaf.registry 1.0.0, since both declare the /apaf-registry router.
