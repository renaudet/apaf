apaf.workflow — Workflow Plugin

Overview

The apaf.workflow plugin provides a visual, graph-based workflow engine for APAF. Workflows represent automated processing pipelines represented as directed acyclic or cyclic graphs of nodes connected by transitions. Definitions are stored in CouchDB (apaf_workflows database) and can be executed synchronously on demand via REST, or asynchronously triggered by the APAF Scheduler (apaf.scheduler) or Event Broker (apaf.event.broker).

Workflow Execution Model

When a workflow is triggered, execution progresses as follows:

  1. Definition Resolution: The workflow document is retrieved from CouchDB using its unique UUID or name + version pair.
  2. Context Initialization: A shared JSON runtime context object is initialized with the payload provided by the caller.
  3. Graph Traversal: The engine identifies the initial Start node and starts evaluating nodes along connected transitions.
  4. Node Processing: Each node executes its associated logic, reads or writes properties in the shared context, and returns control to the engine via a next(context) callback.
  5. Transitions: Conditional or direct transitions determine the next nodes to execute based on boolean expressions evaluated against the context.
  6. Completion: Execution terminates when a terminal node (Stop or End) is reached, or when the global execution timeout is exceeded.
  7. Context Return: The final state of the context object (including execution logs in _console) is returned to the caller.

The global execution timeout is configured via the runtime property workflow.global.timeout (default: 300 000 ms / 5 minutes).

Runtime Context & Execution Options

The context object passed to the workflow engine contains input data and can carry special execution flags in the _options property:

{
  "status": "pending",
  "customerId": "CUST-84920",
  "_options": {
    "noTimeout": true,
    "noLogging": false
  }
}

During execution, the engine appends diagnostic trace events into the _console array of the context:

  • event.type — log, debug, warning, error, stop
  • event.source — Identifier of the emitting node
  • event.timestamp — Timestamp of the log entry
  • event.data — Formatted message or error stack

Built-in Node Types

The apaf.workflow engine includes 19 standard built-in node types:

Category Node Type Description
Control Flow Start Entry point of the workflow graph. Initiates execution with the provided initial context.
Stop Terminal node marking successful completion of the workflow execution.
End Alternative termination node.
If Conditional branch evaluator. Evaluates a JavaScript boolean expression and branches to the corresponding transition.
Or Multiplexing node continuing execution when any inbound transition is satisfied.
Fork Splits execution into multiple concurrent branches evaluated in parallel.
Join Rendezvous node synchronizing multiple parallel branches before proceeding.
Iteration & Timing For Iterates over an array or numeric range from the context, executing downstream loop bodies.
Delay Pauses workflow execution for a specified duration in milliseconds.
Scripting & Logic Script Executes custom inline JavaScript code with access to the runtime context object.
Snippet Executes a reusable code snippet fragment defined in the APAF fragment repository.
SetProperty Sets or computes a specific property value directly in the execution context.
Debug Emits a formatted trace message to the engine console and logger.
Trash Deletes specific transient or sensitive variables from the runtime context.
Integration RestCall Performs an HTTP/REST request (GET, POST, PUT, DELETE) to an external API endpoint via npa.rest.
Mail Dispatches an email notification using configured APAF mail providers via npa.mail.
Data Persistence DB_Query Executes a CouchDB Mango query or view against a specified database.
DB_Create Inserts a new document record into a CouchDB database.
DB_Update Updates an existing document in CouchDB with optimistic concurrency control.
DB_Delete Deletes a document from a CouchDB database by its identifier and revision.
Sub-Workflow Workflow Invokes another workflow definition synchronously as a nested sub-process.

Custom Workflow Nodes

Developers can extend the workflow engine by contributing custom node types through two mechanisms:

1. Contribution via Plugin Manifest

Plugins can declare custom nodes in their manifest.json using the apaf.workflow.node.provider extension point:

{
  "point": "apaf.workflow.node.provider",
  "id": "my.plugin.custom.node",
  "name": "CustomProcessor",
  "resourcePath": "workflow/nodes/customProcessor.js"
}

2. Contribution via CouchDB Code Fragments

Custom nodes can also be authored dynamically in APAF as code fragments of type workflowNode:

function process(context, next) {
    // Access or mutate context properties
    context.processedAt = new Date().toISOString();
    context.computedTotal = context.quantity * context.unitPrice;
    
    // Resume workflow execution
    next(context);
}

REST API Endpoints

Method Path Role Description
POST /apaf-workflow/query developer Query workflow definitions matching a CouchDB Mango selector.
POST /apaf-workflow/ developer Create a new workflow definition document.
PUT /apaf-workflow/ developer Update an existing workflow definition (requires id and _rev).
DELETE /apaf-workflow/:id developer Delete a workflow definition by its unique identifier.
GET /apaf-workflow/:name/:version developer Retrieve a complete workflow definition including node graph and transitions.
POST /apaf-workflow/execute/:id operator Execute a workflow synchronously given its UUID and return the output context.
GET /apaf-workflow/customNodes developer List all available custom node types (manifest contributions + fragment definitions).

MCP Tools

The apaf.workflow plugin exposes Model Context Protocol (MCP) tools for AI agents and integrations:

  • queryWorkflows — Search and list workflow definitions matching criteria.
  • getWorkflowByName — Retrieve the full graph structure and parameters of a named workflow.
  • executeWorkflow — Execute a workflow synchronously with custom input context and options.

Visual Workflow Editor

The visual designer is available in the APAF Web UI at /apaf-workflow-ui/html/manageWorkflows.html and provides:

  • Drag-and-drop canvas for placing and arranging workflow nodes.
  • Interactive transition drawing with conditional branch configuration.
  • Dedicated property editors for each built-in and custom node type.
  • Integrated test runner with real-time visual progress highlighting and _console log inspection.
  • JSON import and export for workflow definition backups and sharing.

Configuration & Runtime Properties

Property Name Type Default Description
workflow.global.timeout integer 300000 (5 min) Maximum execution duration (in milliseconds) before an in-flight workflow is automatically aborted.
