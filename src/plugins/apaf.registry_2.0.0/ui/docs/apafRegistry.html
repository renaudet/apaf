apaf.registry — Registry Plugin

Overview

The apaf.registry plugin turns an APAF instance into a Registry: a catalog of published features (roles, datatypes, workflows, code fragments, applications and rule-data tables) that other APAF instances can search and install through the apaf.registry.client plugin. The Registry is started with node app.js --application registry.

Registry mode

All the Registry specific resources of this plugin are only operational when APAF runs as the registry application. In any other mode, the Registry REST services answer with an HTTP status 418. When started as the Registry, the plugin:
  • locks the npa.application.name runtime property to registry
  • redirects the home page to the Registry features page
  • adds the Registry Features entry to the Administration menu (administrator role)
  • starts the HTTP listener on the port given by REGISTRY_PORT (default 5008)

Registry features page

The page, available to administrators, lists the features stored in the Registry. A feature can be edited (form or raw JSON) or deleted. Features are stored in the apaf_features CouchDB database.

REST API

MethodPathRoleDescription
POST/catalog/v1(none)Store a published feature
GET/catalog/v1(none)Search features (category, name, summary query parameters)
GET/catalog/feature/:id(none)Get a full feature definition
POST/apaf-registry-features/queryadministratorQuery features with a CouchDB Mango selector
GET/apaf-registry-features/:idadministratorGet a feature by UUID
PUT/apaf-registry-features/administratorUpdate a feature
DELETE/apaf-registry-features/:idadministratorDelete a feature

Update site

The htdocs folder of the plugin is served on /repository and is the update site catalog consumed by the apaf.updater plugin.

Relationship with other plugins

Version 2.0.0 no longer contains the client side (publish, catalog, install, Manage Features page), now provided by apaf.registry.client.
