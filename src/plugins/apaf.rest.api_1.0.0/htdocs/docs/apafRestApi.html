apaf.rest.api — REST Client Plugin

Overview

The apaf.rest.api plugin provides a server-side HTTP proxy for invoking remote REST services. It is the recommended way for APAF servlets, workflows, and snippets to call external APIs without dealing with CORS or credentials exposure in the browser.

REST API

MethodPathRoleDescription
POST/apaf-rest/invokecoreServicesInvoke a remote REST service and return the response

Request Payload

The POST /apaf-rest/invoke endpoint accepts a JSON body describing the remote call:
{
  "host": "api.example.com",      // target hostname (required)
  "port": 443,                    // target port (optional, default 80/443)
  "uri": "/v1/data",               // request path (required)
  "method": "GET",                // HTTP method: GET | POST | PUT | DELETE
  "secured": true,                // use HTTPS when true
  "username": "alice",             // Basic auth username (optional)
  "password": "secret",             // Basic auth password (optional)
  "payload": { ... },            // request body for POST/PUT (optional)
  "options": { ... }             // additional Axios options, e.g. custom headers
}

Response

On success, the endpoint returns the remote service's response body and headers:
{
  "status": 200,
  "message": "ok",
  "data": <response body>,
  "headers": { ... }
}

Usage from a Servlet

 1. let runtime = context.runtime;
 2. let restPlugin = runtime.getPlugin('apaf.rest.api');
 3. restPlugin.invokeRemote({
 4.   host: 'api.example.com',
 5.   uri: '/v1/data',
 6.   method: 'GET',
 7.   secured: true
 8. }, function(err, response) {
 9.   context.httpResponse.json(response);
10. });

MCP Tool

The plugin registers the invokeRestApi MCP tool, which exposes the same proxy capability to AI agents.

Notes

  • All outbound calls are made server-side — the caller's browser never receives credentials sent to the remote service.
  • Self-signed certificates can be accepted by setting acceptCertificate: true in the options field.
