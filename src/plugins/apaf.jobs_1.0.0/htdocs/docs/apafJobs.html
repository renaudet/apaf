apaf.jobs — Jobs Plugin

Overview

The apaf.jobs plugin provides a lightweight server-side job management API. A job is a trackable unit of work: it has a description, a status, an optional progress value, and an owner. Jobs are stored in memory by the underlying npa.jobs service and are therefore not persisted — they are lost on server restart. The service is accessible as:
let jobService = plugin.getService('jobs');

Service Name

'jobs'

REST API

MethodPathRoleDescription
POST/apaf-jobs/operatorCreate a new managed job with a description
GET/apaf-jobs/:idoperatorRetrieve a job by its UUID
PUT/apaf-jobs/operatorUpdate job status and/or progress (owner or administrator only)

Job Lifecycle

A job transitions through the following statuses:
  • pending — job has been created but not yet started
  • running — job is actively executing
  • done — job completed successfully
  • error — job terminated with an error
The optional progress field (0–100) can be updated incrementally to track long-running operations.

Workflow Node

apaf.jobs contributes the "Set Job Progress" workflow node, which updates the progress value of a job from within a workflow execution context.

Usage Example

// Create a job from a servlet
 1. let jobService = context.runtime.getService('jobs');
 2. let job = jobService.createJob('Processing my file', context.user.login);
 3. // ... do work ...
 4. jobService.updateJob(job.id, { status: 'done', progress: 100 });

Notes

  • Only the job's owner or a user with the administrator role can update a job.
  • Jobs are in-memory only — a server restart clears all job records.
  • For long-running background tasks, combine apaf.jobs with apaf.scheduler to track progress from a scheduled snippet.
