apaf.tokens — Tokens Plugin

Overview

The apaf.tokens plugin manages security tokens — named, encrypted credential records stored in CouchDB. A token bundles a login, a password, and an optional URI, all encrypted at rest. Tokens allow servlets and workflows to reference external service credentials by name without embedding plaintext secrets in code.

Data Model

Each token record contains:
  • login — username for the external service
  • password — AES-encrypted password (never returned in plaintext via the API)
  • uri — optional target URI (e.g. service endpoint)
  • created — creation timestamp
Records are stored in the apaf_tokens CouchDB database.

REST API

MethodPathRoleDescription
POST/apaf-tokens/token/queryadministratorQuery token records with a CouchDB Mango selector

Using Tokens from a Servlet

A servlet can retrieve a token's decrypted credentials at runtime:
 1. let runtime = context.runtime;
 2. let datatypePlugin = runtime.getPlugin('apaf.datatype');
 3. let crypto = runtime.getService('crypto');
 4. datatypePlugin.findByPrimaryKey('token', { login: 'my-service' }, function(err, token) {
 5.   if (token) {
 6.     let clearPassword = crypto.decrypt(token.password);
 7.     // use clearPassword to call the external service
 8.   }
 9. });

Notes

  • All token management endpoints require the administrator role — tokens are never exposed to non-admin users.
  • Passwords are encrypted using the NPA default AES key via the npa.crypto service. The encrypted value is stored in CouchDB; decryption happens only at runtime in plugin code.
  • The token query API does not return the encrypted password field, even to administrators.
