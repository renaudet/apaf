apaf.rule.data — Rule Data Plugin

Overview

The apaf.rule.data plugin manages named sets of string values called rule data. Rule data records act as server-side lookup tables: they store a list of values under a unique name that can be retrieved at runtime by name and used in workflow logic, servlets, or UI components (e.g. dropdown lists).

Data Model

Each rule data record contains:
  • name — unique identifier used at runtime to fetch the record
  • description — free-text description of the rule's purpose
  • values — array of string values
Records are stored in the apaf_rule_data CouchDB database.

REST API

DELETE/apaf-rule-data/:idadministratorDelete a rule data record

Workflow Node

apaf.rule.data contributes the "Read a RuleData set" workflow node. This node fetches a rule data record by name and writes the values array into the workflow execution context, making it available to subsequent nodes.

Usage Example

Fetching rule data values from a servlet:
 1. let npaRest = context.runtime.getPlugin('npa.rest');
 2. npaRest.get('/apaf-rule-data/rule/my-rule-name', {}, function(err, result) {
 3.   if (!err) {
 4.     let values = result.data.values; // array of strings
 5.   }
 6. });

MCP Tools

The plugin registers six MCP tools covering the full lifecycle: queryRuleData, getRuleDataById, getRuleDataByName, createRuleData, updateRuleData, deleteRuleData.

Notes

  • Rule data names must be unique across the apaf_rule_data database. Attempting to create a duplicate name returns an error.
  • The /apaf-rule-data/rule/:name endpoint is readable by any authenticated user — it is designed for runtime consumption by UI components and servlets.
