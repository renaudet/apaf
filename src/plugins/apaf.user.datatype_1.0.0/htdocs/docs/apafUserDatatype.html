apaf.user.datatype — User Datatype Plugin

Overview

The apaf.user.datatype plugin allows developers to define custom data schemas (user datatypes) and store typed records in CouchDB without writing any server-side code. Each user datatype is a JSON schema that describes a set of typed fields; the plugin automatically provisions a CouchDB database and exposes full CRUD REST APIs for both the schema definition and the data records.

Datatype Definition

A user datatype schema contains:
  • name — technical name (lowercase, no spaces); used in API paths
  • label — human-readable display label
  • description — optional description
  • persistent — true if records are stored in CouchDB
  • database — CouchDB database name (required when persistent is true)
  • private — true if records are visible only to their creator
  • fields — array of field definitions

Field Types

Telemetry

The plugin tracks four telemetry dimensions, one per CRUD operation: datatype.create, datatype.read, datatype.update, datatype.delete.

MCP Tools

The plugin registers MCP tools for both layers: schema tools (queryDatatypes, getDatatypeById, getDatatypeByName, createDatatype, updateDatatype, deleteDatatype) and data tools (queryUserData, getUserDataById, createUserData, updateUserData, deleteUserData).

Notes

  • When private: true, records created by one user are not returned in queries made by a different user, even if both users hold the operator role.
  • The CouchDB database declared in database is created automatically on the first request if it does not already exist.
  • Deleting a datatype definition does not delete the corresponding CouchDB database or any stored records.
