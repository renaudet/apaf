apaf.workflow — Workflow Plugin

Overview

The apaf.workflow plugin provides a visual workflow engine for APAF. Workflows are directed graphs composed of nodes connected by transitions. They are stored in CouchDB and executed synchronously on demand (via REST) or asynchronously (via the scheduler or the event broker).

Workflow Execution Model

Execution follows these steps:
  1. A workflow is fetched from CouchDB by name + version (or UUID).
  2. An execution context object is initialized from the caller-supplied input data.
  3. The engine traverses the node graph, calling each node's handler in turn.
  4. Each node can read from and write to the shared context; transitions carry the context from node to node.
  5. Execution ends when a terminal node is reached or the global timeout expires.
  6. The final context is returned to the caller.
The global timeout is controlled by the runtime property workflow.global.timeout (default: 300 000 ms).

REST API

MethodPathRoleDescription
POST/apaf-workflow/querydeveloperQuery workflow definitions
POST/apaf-workflow/developerCreate a new workflow definition
PUT/apaf-workflow/developerUpdate a workflow definition
DELETE/apaf-workflow/:iddeveloperDelete a workflow definition
GET/apaf-workflow/:name/:versiondeveloperGet a workflow by name and version (includes node graph)
POST/apaf-workflow/execute/:idoperatorExecute a workflow synchronously and return the final context
GET/apaf-workflow/customNodesdeveloperList all available custom workflow node types

Built-in Node Types

The workflow engine ships with standard node types covering common operations: start, stop, conditional branch, set context variable, execute snippet, call REST API, read CouchDB record, send mail, and more.

Custom Workflow Nodes

Any APAF plugin can contribute new node types via the apaf.workflow.node.provider extension point:
{
  "point": "apaf.workflow.node.provider",
  "id": "my.plugin.workflow.node",
  "label": "My Custom Node",
  "handlerUrl": "/myPlugin/workflow/myNode.js"
}
The handler URL points to a JavaScript file (served as a static resource) that exports a node implementation function. At runtime, the node receives the current execution context and a next(context) callback.

MCP Tools

The plugin registers three MCP tools: queryWorkflows, getWorkflowByName, executeWorkflow.

Notes

  • Workflow definitions are versioned — a name/version pair uniquely identifies a definition.
  • The context object passed to POST /apaf-workflow/execute/:id must include a status field initialized to "pending".
  • The _console array in the returned context contains execution log events useful for debugging.
