apaf.event.broker — Event Broker Plugin

Overview

The apaf.event.broker plugin bridges the NPA internal event bus to the APAF application layer. It exposes REST endpoints for emitting and cleaning events, and contributes three workflow nodes that allow event-driven process design. The underlying event service is provided by npa.event.broker and is accessible as:
let broker = plugin.getService('broker');

Event Format

All events share the same structure:
{
  name: 'my.event.name',   // unique event identifier
  source: 'my.plugin.id', // emitting plugin or component
  data: { ... }       // arbitrary payload
}

REST API

MethodPathRoleDescription
POST/apaf-event/emitoperatorEmit an event by posting a JSON event object
POST/apaf-event/clean/:eventNameoperatorRemove all registered handlers for the named event

Workflow Nodes

apaf.event.broker contributes three custom nodes to the workflow engine:
Node labelDescription
Emit an eventEmits a named event with data from the workflow context
Listen to an eventSuspends workflow execution until a named event is received
Clean unused handlers for an eventRemoves all registered handlers for a named event

Using the Broker from Plugin Code

Emitting an event

let broker = plugin.getService('broker');
broker.fire({
  name: 'my.event',
  source: 'my.plugin',
  data: { key: 'value' }
});

Listening to an event

let broker = plugin.getService('broker');
broker.addEventListener('my.event', 'handler-id', function(event) {
  // event.data contains the payload
});

Removing a handler

broker.removeEventListener('my.event', 'handler-id');

Notes

  • Events are synchronous and in-process — they are not persisted and do not survive a server restart.
  • If a handler throws an exception, the broker logs the error and continues notifying the remaining handlers.
  • The event name apaf.fragment.changed is emitted by apaf.dev after every fragment mutation and can be used to invalidate caches reactively.
