apaf.apl — APAF Programming Language Plugin

Overview

The apaf.apl plugin provides a ready-to-use execution service for APL (APAF Programming Language), a JavaScript-like scripting language embedded in APAF. It wraps the generic npa.compiler service with the APL grammar and runtime, exposing a simple two-method interface that any APAF plugin can consume.

APL is the language used to write micro-service scripts in APAF: each micro-service record stores an APL function named process(request, response) that is compiled and executed on every incoming HTTP call.

Service registration

apaf.apl registers itself as the apl NPA service. Consumer plugins can retrieve it in two ways.

Via the service registry (preferred for plugins that declare a dependency)

 1. // manifest.json — add to requires
 2. { "type": "plugin", "id": "apaf.apl", "version": "1.0.0" }
 1. // plugin.js
 2. let aplService = this.getService('apl');

Via the plugin registry (for loose coupling)

 1. let aplPlugin = this.runtime.getPlugin('apaf.apl');

API Reference

compile(source, callback)

Compiles an APL source string without executing it. Useful for syntax-checking a script before saving it. The callback follows the Node.js convention callback(err, result).
Callback argumentTypeDescription
errstring | nullInternal error message. null on success.
result.successbooleantrue if the source compiled successfully.
result.errorstring | nullCompilation error message. null on success.
 1. aplPlugin.compile(source, function(err, result) {
 2.   if (err) { /* internal error */ return; }
 3.   if (!result.success) {
 4.     console.error('Syntax error: ' + result.error);
 5.   }
 6. });

execute(source, builtins, callback, context)

Compiles and executes an APL source string in one call. The callback is always invoked asynchronously — it fires after all async built-ins have completed, or immediately for purely synchronous scripts. Parameters:
ParameterTypeDescription
sourcestringAPL source code to compile and execute.
builtinsobjectMap of native JS functions exposed to the script. Each entry is either a plain function (sync) or { fn, async: true } (async). The function receives its arguments as a JavaScript array.
callbackfunctionNode-style callback(err, result). Invoked once all execution — including async built-ins — has completed.
contextobjectOptional. Map of variable name → initial value pre-loaded into the script's root namespace before execution. After execution, the final value of each variable is accessible as result.memorySpace['.' + varName].
Callback result fields:
FieldTypeDescription
successbooleantrue if execution completed without error.
errorstring | nullRuntime error message. null on success.
memorySpaceobjectSnapshot of the root namespace after all execution has finished (including async callbacks). Variable x is stored under the key ".x".
 1. let responseObj = {};
 2. let globalContext = { request: req, response: responseObj };
 3. let context = { request: req, response: responseObj, globalContext: globalContext };
 4. let builtins = {
 5.   print: function(args) { console.log(args[0]); }
 6. };
 7. let source = microService.source + '\nprocess(request, response);';
 8. 
 9. aplPlugin.execute(source, builtins, function(err, result) {
10.   if (err) { /* compilation or execution error */ return; }
11.   let response = result.memorySpace['.response'];
12.   res.json({ status: 200, data: response });
13. }, context);

Memory space key convention

Variables stored in the script's memory space are prefixed with a dot and the namespace name. Root-level variables (declared outside any function) use just a dot prefix: result.memorySpace['.x']. This dot-prefix is an internal convention of the APL execution engine and must be accounted for when reading results back.

Important: the memory space snapshot is taken after all async callbacks have completed, so it always reflects the final state of the script, including any mutations made by async callbacks (e.g. writing to response via globalContext).

Built-in functions

Built-in functions are passed as a plain object where each key is the function name as it will be called from the APL script. The function receives all arguments as a single JavaScript array. Synchronous built-in:
 1. let builtins = {
 2.   // called as print("hello"); in APL
 3.   print: function(args) { console.log(args[0]); }
 4. };
Asynchronous built-in:

For async built-ins, the APL calling convention is: myBuiltin(arg1, arg2, "callbackFunctionName") — the last argument must always be the callback name as a string. The engine extracts it, builds a native wrapper, and calls engine.cal(callbackName, [results...]) when the I/O completes.
 1. let builtins = {
 2.   // called as fetchData("url", "onResult"); in APL
 3.   fetchData: {
 4.     fn: function(args) {
 5.       // args[0] = "url", args[1] = native JS callback
 6.       let nativeCb = args[1];
 7.       someAsyncCall(args[0], function(err, data) {
 8.         nativeCb(err, data);
 9.       });
10.     },
11.     async: true
12.   }
13. };

Logging

All APL compilation and execution traces are routed through the NPA logging service under the apaf.apl log directory. Set the log level to debug in the site configuration to see detailed compilation and runtime output.
