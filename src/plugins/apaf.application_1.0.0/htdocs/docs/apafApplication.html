apaf.application — Application Framework Plugin

Overview

The apaf.application plugin is the bootstrap entry-point for the APAF application runtime. It registers the application with the NPA core, initializes the HTTP listener, and ensures that critical infrastructure plugins (datatype, scheduler) are fully started before any feature plugin becomes active.

Application Lifecycle

When the NPA runtime starts, each registered application's start() method is called. apaf.application:
  1. Reads the application name from the APPLICATION_NAME environment variable (defaults to "APAF")
  2. Configures the HTTP listener port from HTTP_SERVER_PORT (default: 9080)
  3. Waits for the apaf.datatype and apaf.scheduler plugins to complete their startup
  4. Starts the HTTP server

Home Page

The plugin contributes the APAF home page at /resources/html/home.html via the npa.http.home extension point. This is the page served at the application root URL.

Internationalization

Locale files are provided for en-US, en, fr-FR, and fr. All i18n keys contributed by apaf.application are shared across all APAF plugins — new locale keys for any APAF feature plugin are added to the locale files of apaf.application (not to plugin-specific locale files, unless the plugin ships its own).

APAF Application Records

An APAF Application is a CouchDB record that describes a user-facing single-page application. Applications are managed by the apaf.dev plugin and typically consist of:
  • A name, version, description, and optional role restriction
  • A list of fragment UUIDs (libraries, snippets) loaded by the page
  • Optional support flags (requiresGraphicSupport, requiresDateTimeSupport)
  • A published flag — only published applications appear in the application menus
Applications are rendered by the APAF card framework and loaded dynamically by the apaf.apps plugin.
