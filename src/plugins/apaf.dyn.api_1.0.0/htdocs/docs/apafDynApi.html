apaf.dyn.api — Dynamic API Plugin

Overview

The apaf.dyn.api plugin turns servlet fragments into live HTTP endpoints without any server restart. A servlet is a JavaScript code fragment stored in CouchDB with a unique alias; the plugin routes incoming HTTP requests to the matching fragment and executes its source code in a sandboxed context.

How It Works

  1. A developer creates a fragment of type servlet with a unique alias and sets its enabled flag to true.
  2. At runtime, any HTTP call to /apaf-api/servlet/<alias> is intercepted by apaf.dyn.api.
  3. The plugin resolves the fragment from CouchDB by alias, verifies it is enabled, and evaluates the fragment's source JavaScript.
  4. The invocation count is pushed to the telemetry dimension servlet.invocation.

Servlet Execution Context

The servlet JavaScript code receives the following context object:
{
  user: <APAF User record of the caller>,
  runtime: <NPA runtime instance>,
  require: <Node.js require function>,
  httpRequest: <Express req object>,
  httpResponse: <Express res object>
}
The servlet is responsible for writing the HTTP response using httpResponse.

Minimal Servlet Example

 1. // alias: my-hello-servlet
 2. let user = context.user;
 3. let res = context.httpResponse;
 4. res.json({ message: 'Hello, ' + user.login });

Telemetry

  • servlet.invocation — counts servlet calls per 30-second interval

Notes

  • A servlet fragment must have enabled: true — requests to a disabled servlet return HTTP 404.
  • All four HTTP methods (GET, POST, PUT, DELETE) are routed to the same alias and the same fragment code; use httpRequest.method to distinguish them.
  • The coreServices role is required by default. Servlets that need a different role must implement their own authorization check inside the fragment source.
